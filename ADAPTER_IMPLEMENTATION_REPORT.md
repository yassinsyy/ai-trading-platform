# 📋 ОТЧЕТ О РЕАЛИЗАЦИИ СИСТЕМЫ АДАПТЕРОВ МАРКЕТПЛЕЙСОВ

## 🎯 Цель
Создание гибкой архитектуры адаптеров маркетплейсов с поддержкой трех режимов работы:
- **FEED** - работа через XML фиды (для демо/разработки)
- **SIM** - локальный симулятор (для тестирования)
- **API** - реальные API маркетплейсов (для продакшена)

## 🔧 Конфигурация

### Переменные окружения
```bash
# Режим работы адаптера
MP_KASPI_MODE=feed      # feed|api|sim

# Размер батча для обработки
KASPI_BATCH_SIZE=100

# URL для симулятора
SIM_BASE_URL=http://localhost:3001

# API конфигурация (для будущего использования)
KASPI_API_BASE_URL=https://kaspi.kz/shop/api/v2
KASPI_API_TOKEN=your-token-here
```

## 🚀 Как использовать

### 1. **Feed режим (по умолчанию)**
```bash
export MP_KASPI_MODE=feed
npm run start:dev
```
- Цены обновляются через XML фиды
- Фиды публикуются в S3/MinIO
- Подходит для демо и разработки

### 2. **Sim режим (для тестирования)**
```bash
export MP_KASPI_MODE=sim
npm run start:dev
```
- Локальный симулятор на `/sim/kaspi/*`
- Фикстуры для тестов
- Симуляция ошибок сети

### 3. **API режим (когда появятся документы)**
```bash
export MP_KASPI_MODE=api
export KASPI_API_TOKEN=your-token
npm run start:dev
```
- Реальные API вызовы к Kaspi
- Rate limiting и retry логика
- Обработка ошибок

## 🧪 Тестирование

### Запуск контракт-тестов
```bash
npm test -- adapter.contract.spec.ts
```

### Тестирование симулятора
```bash
# Получить остатки
curl "http://localhost:3001/sim/kaspi/stocks?ids=KSP-001,KSP-002"

# Получить конкурентные цены
curl "http://localhost:3001/sim/kaspi/competition?ids=KSP-001,KSP-002"

# Обновить цены
curl -X POST "http://localhost:3001/sim/kaspi/prices/update" \
  -H "Content-Type: application/json" \
  -d '{"updates":[{"offerExternalId":"KSP-001","newPrice":1500,"reason":"Test"}]}'
```

## 🔄 Интеграционный тест

Полный цикл тестирования:
1. **Seed данных** - создание тестовых офферов
2. **Competitor Poller** - получение конкурентных данных
3. **Pricing Rebalance** - пересчет цен
4. **Price Apply** - применение новых цен
5. **WebSocket** - broadcast обновлений

## 📈 Преимущества новой архитектуры

### 1. **Гибкость**
- Легко переключаться между режимами
- Независимость от конкретных API
- Возможность тестирования без внешних зависимостей

### 2. **Надежность**
- Единый интерфейс для всех адаптеров
- Контракт-тесты гарантируют совместимость
- Graceful degradation при ошибках

### 3. **Масштабируемость**
- Легко добавлять новые маркетплейсы
- Поддержка batch processing
- Rate limiting на уровне адаптеров

### 4. **Разработка**
- Локальный симулятор для быстрого тестирования
- Feed режим для демо
- Четкое разделение ответственности
